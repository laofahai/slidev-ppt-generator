# Presentation Design Notes

这份参考文件用于约束 `slidev-ppt-generator` 生成更像正式演示稿，而不是“自动摘要 + 默认黑底白字”。

## 目标

- 一页只传达一个主结论
- 文字少而准，不堆砌解释性段落
- 用网格、留白、层级来组织信息
- 先保证可讲，再追求花哨
- 不允许内容溢出屏幕边界

## 核心规则

### 1. One Idea Per Slide

- 每页只有一个中心命题
- 如果一个页面同时在讲“定义 + 架构 + 价值”，拆页
- 标题必须像结论，而不是像目录项

好标题：

- `为什么聊天机器人无法承担持续工作`
- `四层结构，才让 AI 真正能执行`
- `本地优先不是技术偏好，而是边界控制`

差标题：

- `什么是 OpenClaw`
- `核心功能`
- `系统介绍`

### 2. 控制文字密度

- 单页正文尽量不超过 40-60 个汉字的连续大段
- 每个卡片内部最多 2-3 行正文
- 一页元素数量尽量不超过 6 个主块
- 如果用列表，保持 3-5 项；超过就换成两页或分组

### 3. 建立视觉层级

- 标题字号必须明显高于正文
- 同一页只保留 1 个最大视觉焦点
- 辅助标签、注释、来源说明统一用低对比浅色
- 不要每个块都用同样的字体大小和粗细

### 4. 留白优先

- 四周至少预留 8%-10% 的安全边距
- 卡片和卡片之间保持稳定间距
- 重要内容周围要有呼吸空间
- 不能为了“填满屏幕”去堆字

### 5. 优先选择适合的 Slidev 布局

优先使用：

- `cover`
- `default`
- `center`
- `end`

仅在内容天然适合时使用：

- `two-cols`
- `image-left`
- `image-right`
- `fact`

不要滥用布局。大多数高质量页面其实只需要 `default` + 自定义网格。

### 6. 内容页优先结构

优先选择这些成熟结构：

- 问题 / 后果 / 转折
- 对比双方 + 决策结论
- 四层架构 / 三段流程 / 五项能力
- 人群 / 场景 / 收益
- 模块拆解 / 职责边界 / 运行结果

### 7. 溢出控制

- 标题超过两行时，先重写标题，不要盲目缩字
- 两栏页中，每栏内容高度必须接近，避免一边撑满一边空
- 页面底部说明、来源、脚注不得把主要内容顶出屏幕
- 结尾页尤其容易溢出：不要同时放大标题、两个大卡片、长脚注、口号

### 8. 对于 Slidev 的具体建议

- 使用内联 HTML 时，结构要简单，避免过深嵌套
- 用固定 `gap`、`p-*`、`rounded-*` 形成一致风格
- 用 `max-w-*` 控制段落宽度，避免横向过长
- 如果文本长度不可控，可考虑 `AutoFitText`，但优先先重写文案

## 生成后的自检清单

在完成 `slides.md` 后，至少做这几项检查：

1. 有没有“只有标题几乎没信息”的空页
2. 有没有某页承担了两个以上核心命题
3. 有没有超过 5 个并列模块还放在一页
4. 有没有段落横向过长导致难读
5. 最后一页是否溢出、挤压、脚注过多
6. 架构页是否真的在讲结构，而不是只是在列名词

## 本技能建议输出风格

- 不追求花哨动效
- 追求稳定、专业、可讲
- 用“克制但有辨识度”的视觉系统
- 让 deck 看起来像有经验的人做的，而不是自动拼出来的
